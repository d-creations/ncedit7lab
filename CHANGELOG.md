## [Unreleased]

### Added
- **Configurable Simulation Resolution, Defaults & Memory Budget (`IConfigService.ts`, `public/config.json`, `NCToolpathPlot.ts`)**:

### Fixed
- **Default Tool Library Turning Tip Positions/Rotations & Mill/Drill Orientations (`DefaultToolLibrary.ts`, `WebToolLibraryRepository.ts`)**:
  - Updated `FRONT_ORIENTATION` (`Front Drill` / `Front End Mill`, e.g. `T1100`, `T1200`) from `[0, 90, 0]` to `[0, 180, 0]` so front tools point along `+Z` into the main spindle face by default.
  - Updated `COUNTER_FACE_ORIENTATION` (`Counter Face End Mill` / `Counter Face Drill`, e.g. `T1300`, `T1400`, `T3300`) and standard cross mills/drills to `[0, 90, 0]` instead of `[270, 0, 0]` / `[0, 0, 0]`.
  - Corrected default turning insert rotations (`V`: `[0, 19, 0]`, `D`: `[0, 28, 0]`, `C`: `[0, 47, 0]`, `L`: `[0, -45, 0]`), added the pocket nose offset `position: [-8, 0, 0]` on front-right inserts (`[8, 0, 0]` on back-left), and added the matching holder Z seat offsets (`[0, 0, 3]` for `V`, `[0, 0, 5]` for `D`, `[0, 0, 2]` for `C`, `[0, 0, 10]` for `L`).
  - Updated `WebToolLibraryRepository.isStaleDefault` to detect `cutting` position/rotation changes so untouched default tools in existing browser `localStorage` automatically upgrade on load.
- **Stationary Center/Drill Removal Under Main-Spindle `M3` (`T1100` / `T1200`) & Display Sharpness**:
  1. **Coaxial Main-Spindle Drilling (`MaterialRemovalPreparation.ts`):** On STAR lathes, front center/drilling tools (`T1100`, `T1200`) run with `M3` (main spindle rotating), so the backend sets `segment.machiningMode = 'turning'`, while the tool is a `drill` with `pose.reference = 'millingTip'`. Previously, `prepareMaterialRemoval` stopped at `T1100` (occurrence 132, line 150) with `"Machining mode, cutter type and pose reference do not agree"`, preventing both `T1100` and `T1200` from removing material. When a non-insert tool with `millingTip` poses moves coaxially along the spindle axis (`X=0, Y=0` in stock spindle coordinates with its tool axis parallel to `spindleAxis`), `prepareMaterialRemoval` now normalizes its motion mode to `'milling'` so `T1100` and `T1200` (and subsequent `T100` part-off) execute.
  2. **Higher GPU Stock Display Resolution (`NCToolpathPlot.ts`):** Now that `0.02 mm` frames render in ~170–290 ms without TDR, removed the `150,000`-pixel clamp on `onRefined` and raised `gpuStockPixelBudget` to start at `450,000` pixels and scale up to `800,000` pixels (with a `250,000` floor).
- **GPU TDR (`DXGI_ERROR_DEVICE_HUNG`) Prevention & Architecture Hardening**:
  1. **Analytical Surface Normals on Unallocated Turned Tiles (`GpuDexelStock.ts`):** Previously, for every hit pixel on the turned body, `gpuDexelNormal` called `gpuDexelAxisSample` across all 3 axes (`X`, `Y`, `Z`), evaluating 15 separate `gpuDexelIntervals` calls per pixel (including 5 full $O(\text{slabs})$ Z-ray scans!). For unallocated tiles (`s0 == s1 == s2 == 0xffffffffu`), `gpuDexelNormal` now computes the exact analytical surface normal directly from the current axial slab's radial lines in $O(\log(\text{slabs}))$ without any ray-interval rebuilds.
  2. **Skip Unallocated Z-Ray in Partially-Allocated Tiles (`GpuDexelStock.ts`):** When only 1 or 2 axes at `p` were allocated (at the border of milled pockets), the fallback loop in `gpuTraceDexels` still evaluated the unallocated $O(\text{slabs})$ Z-ray (`axis == 2 && s2 == 0xffffffffu`) on every `0.02 mm` step. Skip axis 2 whenever `s2 == 0xffffffffu` (since X/Y rays already bound the turned profile), and lower the per-pixel iteration cap from `32,768` (which allowed a single frame to exceed Windows' 2-second TDR limit and trigger `DXGI_ERROR_DEVICE_HUNG` in `150412.log`) to `2,048`.
  3. **Pause Plot Rendering When Switching Side Tabs (`NCEditorApp.ts`, `NCToolpathPlot.ts`):** Switching from the Plot tab to the Tool Editor (`#side-view-tools`) hid `#side-view-plot` with `display: none` without setting `hidden` on `<nc-toolpath-plot>`, so background `0.02 mm` GPU refinement still submitted a full WebGPU render while the Tool Editor's WebGL preview was active on the same Intel GPU. Notify `NCToolpathPlot.setTabActive(view === 'plot')` so hidden side tabs defer rendering until the Plot tab is shown again, and cap pixel budget at `150,000` when `0.02 mm` fine stock is installed.
- **GPU Stock Visual Corruption & cancelled-copy readback**:
  1. In `gpuTraceDexels` (`GpuDexelStock.ts`), WGSL `select(gpuOriginalPointIntervals(0u, ...), gpuOriginalPointIntervals(2u, ...), slabs == 0u)` evaluated **both** arguments into the same `&spans` array before selecting the return count, overwriting axis-0 (X) intervals with axis-2 (Z) intervals on every unallocated tile and making the stock look scrambled. Replaced `select(...)` with `if (slabs == 0u) ... else ...`.
  2. In `GpuDexelStock.copyFrom`, when a seek was superseded during `updateBase` (`this.baseTransitionSource`), `getArrayBufferAsync(this.errorAttribute)` was still called before checking `cancelled()` / `disposed` — and if `makeRoom` had evicted `source`, `stock.dispose()` could dispose the shared `errorAttribute` buffer while `mapAsync` was in flight, deadlocking the WebGPU queue. Check `cancelled()` / `disposed` before `getArrayBufferAsync`, and cap `gpuStockPixelBudget` at `100,000` so rapid coarse seeks cannot inflate the budget before a `0.02 mm` fine frame renders.
- **GPU Display Shader Quadratic Re-Evaluation & Empty-Space Skipping**: In `GpuDexelStock.ts`, `for (var i = 0u; i < gpuDexelCount(...); i++) { let span = gpuDexelSpan(..., i, ...); }` called `gpuOriginalIntervals` both in the loop condition and in the body for every unallocated tile, turning an $O(\text{intervals})$ ray query into $(2N + 1)$ full rotational-base rebuilds per ray per step (and causing FXC/D3D12 to inline `gpuOriginalIntervals` 28 times into the fragment shader). Compute the ray's interval array once per ray via `gpuDexelIntervals` in display and copy shaders. In `gpuTraceDexels`, when all three axis tiles at `p` are unallocated (94% of tiles at 0.02 mm), evaluate only $O(\log(\text{slabs}))$ transverse X/Y rays instead of the $O(\text{slabs})$ Z-ray, and leap across empty space outside the current axial slab's turned outer radius up to the next 32×32 tile or slab boundary instead of stepping 0.02 mm cell-by-cell.
- **GPU Stock Display Cost Bound**: The dexel stock is ray-marched per screen pixel (about one cell per step, three lookups each), so one frame costs pixels × detail, regardless of buffer size. A 1075×628 view at 1.5× scaling was about 1.5 million pixels, and a coarse frame already took 2.1 s on Intel graphics. Limit the stock render to a pixel budget (starting at 100k, 20k–600k), reduce it after any frame over 300 ms, and raise it after fast frames. Log render submit/complete to the console so the last frame before a stall is visible. Calculation pitch is unchanged; only on-screen sharpness is reduced. Not validated on hardware.
- **Mixed-Stock Preparation Responsiveness**: Remove the synchronous initial turning prepass and build the implicit base in the yielding, cancellable replay path. Cache compiled-sweep and profile-slab memory totals instead of rescanning them inside every profile workspace reservation; skip eviction scans while within memory/cache bounds. Preserve material geometry, pitch and memory limits, with regression coverage for bounded initial cancellation and scan counts. Hardware browser hangs are not validated by these CPU/mocked-GPU tests.
- **Redundant Plot Invalidations**: Ignore theme notifications when the resolved background color is unchanged and resize notifications when the renderer size is unchanged. Disable post-input OrbitControls inertia for WebGPU stock views; camera input remains immediate, while WebGL retains damping. Cover actual OrbitControls change-event feedback and observer no-op paths without running GPU hardware.
- **Idle Plot GPU Contention**: Replace continuous 3D rendering with coalesced, on-demand frames. Preserve camera damping and redraws for stock, tool, selection, visibility, theme and resize changes; stop scheduling when idle/hidden/disconnected and retain changes arriving during an in-flight GPU frame. Stock resolution and removal computation are unchanged.
- **Adaptive Mixed-Stock Interval Memory**: Start replay at the smallest supported 4/8/16/32/64 capacity that fits the implicit base and retained source, rather than reserving 16 intervals for every ray. Retry each tier on explicit overflow with immutable source/display preservation and unchanged pitch, ray grid and memory limits. Same-input nonbrowser allocation evidence for the saved 2 mm / 89-degree mixed fixture reduces fine resident estimates from 172.4 MiB to 131.1 MiB at .02 mm; GPU execution/readback was mocked, so this is not hardware material or timing validation.

## [1.2.1] - 2026-10-05

### Added
- **Geometric Material Removal Preview**: Added bounded, chunked 3D voxel stock removal for a single-channel Simulation plot, including box/cylinder stock, swept flat/ball/corner-radius end mills and drills, and supported conventional turning inserts. Turning and milling subtract from the same stock so earlier pockets and holes remain removed.
- **Removal Setup**: Added explicit program-to-workpiece translation/rotation, workpiece-frame selection, turning spindle origin/axis, and configurable voxel size from 0.05 to 5 mm with a 0.5 mm default.
- **Background Computation**: Added a run-owned Web Worker with progress, cancellation, memory/work limits, and exposed stock-surface generation. Obsolete runs are cancelled without tying computation to editor cursor movement.
- **Removal Capability Diagnostics**: Unsupported operations, unknown feed modes, missing cutter geometry/poses, and frame changes stop removal at the affected execution step and source line. Rapids never remove stock; supported feeds are assumed cutting with a visible spindle-verification warning.

### Changed

## [1.2.0] - 2026-10-05

### Added
- **Cutting Edge Q Orientation (0–9)**: Added theoretical tool-tip alignment for turning inserts based on controller cutting edge direction $Q$ (1–9, 0) and nose radius $R$. The tool assembly shifts automatically so the tangential touch-off point (virtual tip) aligns with $(0, 0, 0)$.
- **Reset Defaults in Tool Library**: Added a `Reset Defaults` button in the Tool Manager Library tab to reset standard default tools to factory presets while preserving custom user tools.

- **Default Tool Mounting Orientations**: Standardized turning inserts to `[0, 90, 0]`, front/radial milling tools to `[0, 90, 0]`, and counter-face tools to `[270, 0, 0]`.
- **Automatic Library Migration**: Extended default-tool detection to automatically upgrade older stored standard library tools (including $12\,\text{mm}$ and $9.5\,\text{mm}$ inserts) to the new geometry, orientation, and $Q/R$ defaults upon loading.

### Fixed
- **Plot Tool Simulation Orientation**: Fixed double-application of tool mounting orientation in `NCToolpathPlot` where `pose.orientation` was premultiplied onto an already-oriented tool mesh, ensuring 3D plot orientation matches the preview 1:1.

- **Alignment Matching**: Two-space padding lines are added only around unique synchronization markers matched from the server-provided syntax and shared in the same order by every active channel; no fallback matching is used.
